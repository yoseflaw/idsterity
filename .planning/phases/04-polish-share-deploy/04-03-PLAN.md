## Phase Goal

**As a** visitor clicking a direct LinkedIn share link to https://yosef.id/sterity/, **I want to** reach the site immediately, **so that** I don't hit a confusing Apache 404 error page instead of the story.

<objective>
Create dashboard/public/.htaccess with Apache mod_rewrite SPA fallback rules — so that when dist/ is FTP'd to /sterity/ on Apache shared hosting, direct URL access works and the SPA loads correctly.

Purpose: Without .htaccess, Apache handles a direct GET /sterity/ by looking for a file named "sterity" at the server root. The mod_rewrite fallback serves index.html for any request that does not match an existing file or directory, enabling the SPA to handle routing. This is the only server-side configuration required for the project.
Output: dashboard/public/.htaccess (6 lines), verified to be present in dist/ after build, with final deploy and Lighthouse checkpoint before FTP.
</objective>

<!-- Apache mod_rewrite pattern for SPA subdirectory deploy: -->
<!--
  Options -MultiViews
  RewriteEngine On
  RewriteBase /sterity/

  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule ^ index.html [L]
-->
<!-- Key constraints: -->
<!-- - RewriteBase MUST be /sterity/ (not /) for subdirectory deploy — without it Apache resolves relative to server root -->
<!-- - [L] flag (not [END]) — compatible with Apache 2.2 and 2.4; shared hosting may run 2.2 -->
<!-- - Options -MultiViews prevents Apache file-extension guessing from interfering with SPA routing -->
<!-- - File location: dashboard/public/ (NOT dashboard/src/) — Vite copies public/ verbatim to dist/ -->
<!-- - The two RewriteCond lines serve existing files (assets, JSON, images) directly — no rewrite needed for them -->
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Apache /sterity/ | HTTP request hits mod_rewrite; non-file requests are rewritten to index.html |
| .htaccess → index.html rewrite | Static rewrite only — no user input is evaluated; mod_rewrite rewrites the request path, not response content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-07 | Elevation of Privilege | .htaccess mod_rewrite | accept | RewriteCond !-f !-d guards ensure existing files (assets, JSON) are served directly — .htaccess cannot be used to rewrite requests to itself or to non-existent server paths; no user-controlled input in RewriteRule |
| T-04-08 | Denial of Service | Apache SPA fallback loop | accept | Options -MultiViews and the !-f !-d conditions prevent infinite rewrite loops; [L] flag stops processing after first match; RewriteBase scopes the rule to /sterity/ only |
| T-04-09 | Information Disclosure | dist/ contents FTP'd to host | accept | dist/ contains only public static files (HTML, JS, CSS, JSON, JPEG) — no secrets, env vars, or credentials; Vite build excludes node_modules and source files |
</threat_model>
