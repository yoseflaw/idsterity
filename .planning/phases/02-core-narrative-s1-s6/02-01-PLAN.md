## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → static JSON | Static `/data/*.json` files served by static hosting; treated as trusted (data baked at build, no user input mixes in) |
| browser → external news URLs | Outbound `<a target="_blank">` to third-party news sites (kompas.com, tempo.co, etc.) — visitors leave the site |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.01-01 | Tampering | safeFetch helper in App.svelte | mitigate | safeFetch checks `r.ok` and throws on non-2xx; try/catch in onMount sets a user-visible `fetchError` state instead of silently stalling. Prevents a 404/500 from causing an opaque JSON parse exception (CR-02) |
| T-02.01-02 | Information disclosure | News link `<a target="_blank">` elements | mitigate | All news anchors use `rel="noopener noreferrer"` so target page cannot access `window.opener` or read referrer headers from idsterity |
| T-02.01-03 | Spoofing | Bilingual copy in i18n.js | accept | All copy is authored by Claude (per D-05) and committed to repo. No runtime user input is interpolated into copy strings — XSS surface is null |
| T-02.01-04 | Denial of service | onMount Promise.all | mitigate | Try/catch ensures one failing fetch sets fetchError but does not block the rest of the UI; CR-01 fix prevents the entire page from stalling on a missing JSON file |
</threat_model>
