## Section Layout Contracts

### Scrolly Section Structure (S1, S2, S3, S5+S6)

Each section uses the two-column layout established in Phase 1:

```
.scrolly-section
  └── .sticky-col   (60% width desktop / 100% stacked mobile)
        ├── [section eyebrow — JetBrains Mono 11px, var(--gold)]
        ├── [chart component or display text block]
        └── .step-indicator (pip row — desktop only, aria-hidden)
  └── .steps-col    (40% width desktop / 100% stacked mobile)
        └── .step[data-step="N"] × (N steps per section)
              └── .step-card
                    ├── .step-num   [JetBrains Mono 11px]
                    ├── h3          [Libre Baskerville 23px, weight 700]
                    └── p / ul      [Source Serif 4 16px, weight 400]
```

**Multiple scrolly instances (D-01):** Each of S1, S2, S3 gets its own `.scrolly-section` wrapper. S5+S6 share one `.scrolly-section`. Each section's sticky panel tracks its own `$state(activeStep)` integer via Scrollama. Section-level active step state is local to each section — `activeStepS1`, `activeStepS2`, `activeStepS3`, `activeStepS5` — not a single global step counter.

**Sticky panel height:** `height: 100dvh` (not 100vh) — consistent with Phase 1 mobile chrome handling.

**Mobile breakpoint (≤800px):** Sections stack vertically. Sticky-col becomes `position: relative; height: auto; min-height: 60vh`. Pip indicator hidden (`display: none`). Steps-col full width.

**Scroll offset:** Scrollama `offset: 0.5` (50% viewport — Pudding standard, consistent with Phase 1).

- Step card: single `data-step="0"` card. Contains a `<ul>` of 3–5 `<li>` items, each an `<a>` link to a news article.
- News links style: `color: var(--text); text-decoration: underline; text-decoration-color: var(--border); text-underline-offset: 3px`. On hover: `text-decoration-color: var(--gold)`. 150ms transition.
- Each `<li>` has `padding: 10px 0` to guarantee 44px touch target height.
- Links open in new tab: `target="_blank" rel="noopener noreferrer"`.
- No pip indicator for S1 (single step — pip row not rendered).

## Isometric Coin Stack — Visual Specification (S2 and S3)

This is a custom SVG illustration pattern, not a D3 chart. The following defines the visual contract for `DeficitChart.svelte` and `GDPChart.svelte`.

**Coin unit:** Each individual coin is a CSS-rendered isometric ellipse — `rx: stackWidth/2`, `ry: stackWidth/6` (standard 3:1 isometric ratio). Stack width: 64px (desktop) / 44px (mobile).

**Coin color:** Top face: `rgba(201,168,76,0.85)` (near `--gold`). Edge face: `rgba(201,168,76,0.45)`. Coin edge height: 8px per layer. No new CSS tokens — these are SVG `fill` attributes using rgba derivations of `--gold`.

**Stack height mapping:** Each Rp 1 trillion = 2px of visual stack height (capped at a maximum of 200px desktop / 140px mobile). Labels show exact IDR figure in trillions.

**Negative value (S3 Q1 2025 −3.24%):** Rendered as an inverted stack below the baseline — same coin shape, fill `rgba(196,66,66,0.6)` (rgba of `--red`). Label reads "−3.24%" in `color: var(--red)`.

**Active/inactive state:** Active stack (matching scroll step): full opacity, subtle scale `transform: scaleY(1.02)` on outermost SVG group (0.3s ease). Inactive stacks: `opacity: 0.4`.

**Period label:** Below each stack. JetBrains Mono 10px, `rgba(237,232,220,0.35)` — "Okt 2024" / "2025" / "TW I 2026".

**Value label:** Above each stack (or to the right for deficit stacks). JetBrains Mono 11px, `rgba(237,232,220,0.7)`. Format: "Rp 309 T" (deficit) or "+10,93%" (GDP growth).

**Baseline rule:** 1px horizontal `<line>` across chart width. Stroke `var(--border)`.

## Interaction Contracts

### Scrollama Multi-Section Architecture

Phase 2 extends the single-scroller pattern from Phase 1 to multiple per-section scrollers.

- Each scrolly section (S1, S2, S3, S5+S6) uses its own `scrollama()` instance.
- Each instance targets `[data-section="N"] [data-step]` using a CSS selector scoped to that section's container.
- Scroller setup runs inside `requestAnimationFrame` (consistent with Phase 1 pattern, WR-03 fix applied).
- `onDestroy` destroys all scroller instances and removes all resize listeners.
- Resize handler calls `.resize()` on every active scroller.

### D3 Re-sort Transition (S6)

- Trigger: `activeStepS5` reaches the S6 step index (e.g. index 2 in the S5+S6 section).
- Action: `InstitutionsChart.svelte` internal `$derived` detects the step change. D3 selection on all `<g class="bar-group">` elements. `transition().duration(600).ease(d3.easeCubicInOut)` applied to `transform: translateY(...)` recalculated from high-pagu sort order.
- Non-flagged opacity: `transition().duration(400)` on `opacity` from 1 → 0.2.
- Reverse: If user scrolls back to S5 steps, bars re-sort back to total-pagu order with same transition.

### News Article Links (S1)

- `<a>` elements with `target="_blank" rel="noopener noreferrer"`.
- No JavaScript click handlers — plain anchor navigation.
- Underline affordance: `text-decoration: underline; text-decoration-color: var(--border); text-underline-offset: 3px`. Hover: `text-decoration-color: var(--gold)`.
- Minimum 44×44px touch target via `padding: 10px 0`.

### Source Citation Links (S2, S3)
