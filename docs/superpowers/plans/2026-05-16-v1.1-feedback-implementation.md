# v1.1 Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply 12 feedback items + 7 mobile observations from `feedbacks/v1.1/FEEDBACK.md` and the v1.1 design spec.

**Architecture:** Three sequential phases. Phase 1 = global cleanup + data pipeline (independent). Phase 2 = podium components (depends on Phase 1's new data file). Phase 3 = word-cloud rebuild + chart fixes (depends on Phase 1's stop-word changes).

**Spec:** `docs/superpowers/specs/2026-05-16-v1.1-feedback-design.md`

## Conventions for All Tasks

- **Verification:** every UI task ends with a browser check at `npm run dev` (http://localhost:5173) on both mobile (Chrome DevTools, 360×800) and desktop (≥1280px). Acceptance criteria are listed per task.
- **Commits:** one commit per task with conventional prefix (`feat:`, `fix:`, `refactor:`, `chore:`).
- **No tests:** project has no test infrastructure. Skip TDD steps. Manual browser verification is the gate.

- [ ] **Step 2: Inspect yScale and bar height computation**

```bash
grep -n -E "yScale|height|scaleLinear|domain" dashboard/src/DeficitChart.svelte
```

Common bugs:
- `yScale.domain([0, max])` when data includes negatives → negatives map to bottom incorrectly.
- Bar `height = yScale(value)` instead of `chartHeight - yScale(value)` (D3 inversion).
- Hardcoded `height={...}` per data point overriding the scale.

- [ ] **Step 3: Fix to be strictly value-driven**

Set domain to `[min(values), max(values)]`. Compute bar height as `Math.abs(yScale(value) - yScale(0))` and y-position as `Math.min(yScale(value), yScale(0))`.

- [ ] **Step 4: Browser verification**

Reload S3. Each bar's pixel-height should be linearly proportional to its absolute value. The negative-deficit bar sits below the zero baseline.
